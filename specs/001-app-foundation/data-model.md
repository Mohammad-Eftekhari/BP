# Data Model: Reusable Application Foundation

## Account (`user`)

Owned by Better Auth. Generated schema is the source, extended with `role`.

| Field         | Rules                                                                                                                    |
| ------------- | ------------------------------------------------------------------------------------------------------------------------ |
| id            | Primary key, text, generated by Better Auth                                                                              |
| name          | Required display name collected at registration                                                                          |
| email         | Required, unique, normalized by Better Auth                                                                              |
| emailVerified | Boolean, default false. Verification mail is out of scope                                                                |
| image         | Optional                                                                                                                 |
| role          | Required text, default `user`. Allowed values in application code: `user`, `admin`. Not accepted from registration input |
| createdAt     | Timestamp, set on insert                                                                                                 |
| updatedAt     | Timestamp, set on change                                                                                                 |

## Session (`session`)

Better Auth session. Cookie identifies the row. Application code does not parse the cookie itself.

| Field                | Rules                                             |
| -------------------- | ------------------------------------------------- |
| id                   | Primary key                                       |
| userId               | Required foreign key to `user.id`, cascade delete |
| token                | Unique secret stored server-side                  |
| expiresAt            | Required                                          |
| ipAddress, userAgent | Optional, written by Better Auth                  |
| createdAt, updatedAt | Timestamps                                        |

## Account credential (`account`)

Better Auth credential row for email/password. Password verifiers live here, never in logs or API responses.

| Field                 | Rules                                                 |
| --------------------- | ----------------------------------------------------- |
| id                    | Primary key                                           |
| userId                | Required foreign key to `user.id`, cascade delete     |
| accountId, providerId | Required. Email/password uses the credential provider |
| password              | Optional secret verifier                              |
| createdAt, updatedAt  | Timestamps                                            |

## Verification (`verification`)

Reserved by Better Auth for future email verification and password reset. No product flow writes it in this version.

## Profile (`profile`)

Application-owned. One row per account.

| Field       | Rules                                                                  |
| ----------- | ---------------------------------------------------------------------- |
| id          | Primary key, UUID                                                      |
| userId      | Required, unique, foreign key to `user.id`, cascade delete             |
| displayName | Required text, 1–80 characters after trim                              |
| bio         | Required text, empty string allowed, maximum 280 characters after trim |
| createdAt   | Timestamp with time zone, default now                                  |
| updatedAt   | Timestamp with time zone, default now, set on update                   |

## Relationships

- One account has many sessions and many credential rows.
- One account has at most one profile.
- Deleting an account deletes sessions, credential rows, and the profile.

## Invariants enforced in the database

- Unique email
- Unique session token
- Unique profile per account
- Foreign keys with cascade delete
- Non-null display name and bio

## Invariants enforced in application code

- Role is `user` or `admin`
- Registration cannot set role
- Profile writes always use the authenticated account id, never a client-supplied account id
- Biography and display name are trimmed before write

## Transactions

A single profile insert or update does not need a transaction. Use `db.transaction` when a future change must write the profile and another row atomically. Do not wrap read-only queries.
